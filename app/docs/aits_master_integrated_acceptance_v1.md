# AITS Master Integrated Runtime Acceptance V1

최종 campaign은 `SPRINT-AITS-MASTER-INTEGRATED-RUNTIME-ACCEPTANCE-V1` 하나로 수행한다. 문제별 micro Goal을 만들지 않고 발견 문제는 하나의 Stabilization Sprint로 묶는다.

## Phase A — 설치와 첫 실행

- 목표 Windows 노트북에서 installer/portable hash 검증
- Python, venv, Ollama 없는 상태에서 설치
- 최초 실행 OFF, 자동 주문 0
- App/Data/Backup 경로, version/channel, Qt plugin, low-resource 상태 확인
- Provider 선택·저장·Preview·연결 상태 분리 확인

## Phase B — 기존 데이터 이전과 업그레이드

- 기존 설치 detector와 migration plan 검토
- Essential backup 생성 및 검증
- staging copy, checksum/count/schema 검증
- Champion/Authority/Capability/Intent/Policy 보존
- app/data rollback 준비

## Phase C — 실제 ON 통합 운영

- startup/low-resource/hard-freeze 확인
- Holdings SSOT, Managed Pool, SellEvaluation
- Effective Policy, Intent, ETA, invalidation, redecision
- GPT/Gemini teacher, LOCAL candidate, Lv2 co-pilot dormant authority
- AI Review/Learning Journal
- 자연 주문 발생 시 Validator→RiskGuard→LivePreflight→Execution→reconciliation→replanning
- LOCAL final source 0, 자동 promotion 0

## Phase D — OFF maintenance

- curation, feature, distillation, training, calibration
- Challenger/Champion 비교, Capability/Level 재평가
- failed/no-data attempt가 usable pointer를 덮어쓰지 않음

## Phase E — Governance와 Release

- Essential/Learning backup과 support bundle 검증
- archive, restore, migration, update, rollback plan
- integrity, schema compatibility, disk pressure
- release artifact manifest/hash와 secret/runtime data 제외

## 종료 기준

모든 단계에서 Source/Authority/Champion/Intent/Policy provenance를 보존하고 실제 주문은 기존 guard 경로만 사용한다. 최종 결과에는 설치 artifact, runtime session, maintenance attempt, order/reconciliation, governance와 rollback evidence를 하나의 acceptance report로 기록한다.
